* Fixing
 1. First check the DNS server. If DNS can't resolve the domain name successfully, no later. useful commands like *host* and *dig*. If this failed, check the configuration file **/etc/resolv.conf/**. You can try to modify the DNS server by specify it in command line.
 2. Then test Network layer. The well-known command *ping*. But the failure doesn't mean the problem. The destination server may not start the ICMP server.
 3. Check transport layer can use the *curl* command. You can use options 's' and 'I' so that the output is clear so that you can focus on problem. Common for saving your time, you can use '--max-time' and '--retry' if you are sure your network is roughly OK. In my case, here I failed, then I suddenly thought that I open the VPN, so I append this prompt to agent. Here, I also check if there exist the difference between IPv4 and IPv6 by '-4' and '-6' options. 
 4. According to the VPN information and the error of curl. I firstly used the *ss* command to find the listening port. Then ensure the shell don't have the proxy *env | grep proxy*. Last test the proxy by the '-x' option of curl. This time the connection is normal. Also checked the configuration file under **~/.mozilla/firefox/** by search for keyword **proxy**.

* Summary
 For this experience, I don't think there are too many things to learn, but I think this is a good time to learn how to find problems layer by layer and to summarize the common used network related commands by layers.

 |-------------+----------------------------|
 | DNS         | host, dig, nslookup        |
 | Link        | ip link, arp               |
 | Network     | ping, traceroute, ip route |
 | Transport   | nc, ss, telnet, nmap       |
 | Application | curl, wget, lynx, openssl  |
 |-------------+----------------------------|
